# 删除已归档会话

在会话行 **⋯** 菜单里加一项 **删除该会话… / Delete this session…**。第二次确认点击之后，它会把这个**已归档**会话的日志文件从磁盘上永久删除，并把该会话从归档集合中摘除。

## 使用

1. 先归档该会话（行菜单 → **归档会话**）。归档是那一步可撤销的操作，会一直保留。
2. 打开这个已归档行的 **⋯** 菜单，选择 **删除该会话…**。
3. 当它变成 **再点一次：永久删除** 时，再点一次。
4. 行消失，文件也没了。

删除通过宿主执行，并从你当前打开的那个会话发出，因为已归档会话没有活着的 agent 可以接收命令。如果没有打开任何会话，或者目标就是当前会话，菜单项会直接说明原因并停下。

## 会删掉什么

- 该会话自己目录下的所有日志产物，例如 `~/.dsh/sessions/<工作区>/<会话 id>/session.v4.jsonl.zstd`。
- 归档集合里对应的一条记录，不会留下悬挂的归档项。

## 会保留什么

- `~/.dsh/attachments` 下的**附件**：它们按内容寻址，可能与其他会话共用，因此不动。
- 搜索索引行与投影缓存交给各自的缓存处理；会话不存在后它们会自行丢弃该行。

## 限制

- 只能删除**已归档**的会话。运行中、正被打开、或仍可见的会话会拒绝并给出说明，而不是删除。
- 正在执行该命令的会话不能删除自己。
- 本次启动期间打开过的会话，归档后其 agent 仍驻留并占着写入句柄。删除仍会继续：归档闸门已经拦住它再跑模型步骤，它能刷的只剩归档时已经停止的工作。若占用来自未知写入方，则拒绝并建议重启。
- 目录里出现会话日志之外的东西就绝不删除，命令会报出这些多余条目。
- 删除不可撤销，没有回收站，也没有恢复路径——除非你自己备份了 profile 目录。
- 插件依赖 JSONL 持久化后端的 `location` 字段。不报告逐会话位置的其他后端会被拒绝，而不是去猜。
